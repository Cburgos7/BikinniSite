<task type="auto">
  <name>Task 2: Create the swatch-color lookup snippet</name>
  <files>snippets/swatch-color.liquid</files>
  <action>
Create `snippets/swatch-color.liquid`. It takes one parameter, `color` (the raw product option value string), and emits a single CSS color value with no surrounding whitespace, suitable for inlining directly inside a `style="background-color: ..."` attribute.

Open with a `{%- comment -%}` / `{%- endcomment -%}` header block in the same documented style as `snippets/cloudinary-img.liquid` — Snippet name, Usage example, Parameters, Behavior. Do not use `/* */` anywhere.

Every Liquid tag in the body must use `{%- -%}` whitespace-stripping delimiters and the single output must use `{{- -}}`, so that rendering the snippet inline inside an HTML attribute emits no stray newlines or indentation.

Logic, in order:

1. Assign `swatch_lookup` to `color | strip | downcase`. This is the normalized name to match.
2. Assign `swatch_result` to an empty string (the not-found sentinel).
3. Guard the whole parse with `{%- if settings.swatch_color_map != blank -%}` so a blank setting short-circuits straight to the fallback.
4. Split the map into lines using the standard Shopify pattern: pipe `settings.swatch_color_map` through `newline_to_br` then `split: '<br />'`. Do not attempt to embed a literal newline in a Liquid string. Assign to `swatch_lines`.
5. Loop `swatch_line` over `swatch_lines`. Inside the loop:
   a. Assign `swatch_line_clean` to `swatch_line | strip`. `strip` also removes stray carriage returns from CRLF-authored input.
   b. Assign `swatch_pair` to `swatch_line_clean | split: ':'`. If `swatch_pair.size` is less than 2, this line has no colon — `{%- continue -%}`.
   c. The hex is always the segment AFTER THE LAST colon: assign `swatch_hex` to `swatch_pair | last | strip`. Taking the last segment (not the second) is what makes a color name containing its own colon work.
   d. The name is everything before that last colon. Derive it from the string, not the array, using Shopify's `remove_last` filter: assign `swatch_name` to `swatch_line_clean | remove_last: swatch_hex | strip | remove_last: ':' | strip | downcase`. This preserves internal spaces and internal colons in the name.
   e. If `swatch_hex` is blank, `{%- continue -%}` (guards a trailing-colon line with no value).
   f. If `swatch_name` equals `swatch_lookup`, assign `swatch_result` to `swatch_hex` and `{%- break -%}`.
6. After the loop and the `if`, when `swatch_result` is blank, assign it to `color | downcase | replace: ' ', '-'` — this is the exact legacy behavior, so any color that renders correctly today keeps rendering correctly.
7. Emit exactly one output: `{{- swatch_result | escape -}}`. The `escape` filter is mandatory — the map is merchant-authored free text flowing into an HTML attribute, and it closes the attribute-breakout / CSS-injection boundary (T-S0A-01 below). It is a no-op for well-formed hex values.

Worked examples the implementation must satisfy, given the seeded default map:
- `Noir` -> `#0d0a08` (exact match)
- `noir` and `NOIR` -> `#0d0a08` (case-insensitive)
- `  Coral  ` -> `#e85d3a` (name trimmed)
- `Hot Pink` (not in map) -> `hot-pink` (legacy fallback, unchanged from today)
- `Midnight Bloom: #123456` line in the map, looked up as `midnight bloom` -> `#123456` (multi-word name)
- `Noir: Limited: #abcdef` line, looked up as `Noir: Limited` -> `#abcdef` (colon inside the name)
